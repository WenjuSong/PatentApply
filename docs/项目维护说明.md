# 项目文档分层与维护

建立日期：2026-10-22。

## 为什么这样分

可以在本线程中提出修改并维护项目级AGENTS.md，但长期有效的是磁盘上的文件，不是某条聊天消息。AGENTS.md适合少量稳定约定；操作经验放Skill，单件事实和状态放档案，模板与原件保留既有目录。

OpenAI官方说明：Codex按全局及项目目录加载AGENTS.md；本项目现已按用户要求建立Git根目录，根AGENTS.md承载项目规则。未使用Git根目录的其他工作区需注意仅从当前目录发现规则的差异。嵌套规则只在确有不同约定时新增。见[官方AGENTS说明](https://developers.openai.com/codex/guides/agents-md)。Skill按名称与描述选择后再加载详情，适合跨会话复用流程和脚本，见[官方Skills说明](https://developers.openai.com/codex/skills)。核对日期为2026-10-22。

## 唯一维护来源

| 层级 | 放什么 | 何时更新 |
|---|---|---|
| AGENTS.md | 项目稳定边界、真实贡献、逐页审核、源件保护 | 用户确立长期约定时 |
| README.md | 入口和链接 | 路径或入口变化时 |
| 全局Skill | 办理流程、问题解法、可重复脚本 | 有新真实经验并验证后 |
| 模板索引与既有模板目录 | 用户确认正文、PDF配置、研发证据及生成器 | 通用修改获用户确认后，保留旧版 |
| 新作品信息卡及cases档案 | 每件事实、缺项、确认来源和回执 | 新件开始、用户确认或状态变化时 |
| 申请台账 | 状态、编号、下一动作 | 对应档案有新证据时 |
| output与既有版权准备 | 原始证据、输出版本、校验清单 | 每次交付留新版本 |

不将私密身份文件或签名塞进AGENTS/Skill。证据留在本机业务目录，Skill只维护方法与入口。Skill正式维护路径是 `~/.codex/skills/beijing-art-copyright/`，本项目不再保存另一份可编辑Skill正文。新件统一使用项目内v2 PDF生成器，旧版作为历史提交的冻结实现保留，不再双线修改。

## 最小维护闭环

1. 新件复制信息卡，先查现有记录，再填本件差异；共用研发截图不重复制作。
2. 每次交付记录用户确认版本、源路径、SHA-256、当前状态与下一动作。旧提交件不覆盖。
3. 用户认可的可复用改进才升级模板；只对本件适用的改动留本件档案。
4. 补正追加补正说明和新版本，保留原申报材料；受理/发证有证据后更新台账。

已按用户要求使用Git及GitHub保存代码和通用文档，采用白名单排除本地业务材料。现阶段不额外引入看板、数据库、自动化提醒或CI。公开仓库边界见[仓库管理说明](仓库管理说明.md)。
