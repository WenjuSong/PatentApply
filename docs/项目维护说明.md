# 项目文档分层与维护

规则以磁盘文件为准。只维护实际生效的来源，其他入口链接或生成副本，不复制多份正文分别修改。

## 唯一维护来源

| 对象 | 维护源 | 更新方式 |
|---|---|---|
| 长期边界与工作约定 | 根目录AGENTS.md | 当前用户确立新约定时修改原条目，清除冲突旧句 |
| 操作步骤与经验 | 本机 `~/.codex/skills/beijing-art-copyright/` | 修正实际遇到的问题；仓库Skill只由导出脚本更新 |
| 通用三栏正文 | `templates/作品说明书.md` | 固定段落沿用，只将获确认的通用改进纳入 |
| PDF结构与通用图注 | `templates/published.example.json`、`unpublished.example.json` | 同步两种发表状态，保持九张共用研发图及四部分结构 |
| PDF实现 | `版权准备/补充材料PDF模板-北京-v2-20261022/build_pdf.py` | 只改当前使用实现，旧脚本冻结 |
| 私人范本与素材入口 | 本地模板索引 | 指向用户确认范本、共用素材及当前模板，不复制正文 |
| 本件事实、审核、签字与回执 | `cases/<作品名称>/` | 留确认来源、实际文件/hash及当前断点；台账仅汇总状态 |
| 历史提交件 | 各件output版本与档案 | 冻结，不回写；补正或修订另建版本 |

公开模板只有占位信息。个人背景段落只有与本件事实相符才沿用；单件创作记录不能被共用研发资料替代。旧本地可编辑模板已在索引标为停用；保留历史文件不等于继续作为当前入口。

## 每次交付的维护闭环

1. 从当前信息卡和页面恢复；对照模板只改本件必要信息。
2. 用户确认后保存正文、配置、输入输出hash、页数及预览证据。
3. 通用经验修改上述唯一来源；个案事实仅写cases。源件与已提交版本不覆盖。
4. 上传、保存、提交、受理、审查、发证分别记录；有对应页面证据才更新台账。
5. 发布前运行Skill校验、导出、模板检查及适用的生成验证；审查实际暂存文件后提交推送。

## Skill发布副本

```sh
python3 scripts/export_skill.py
python3 scripts/export_skill.py --check
```

导出仅包含入口、三份参考文档、UI描述及PNG转换脚本；不会复制整个个人Skill目录。`--check`以字节比较源与副本。维护源与发布副本均不存个人业务数据；新增导出文件须同时审查白名单。

新机器可将仓库发布副本安装到个人Skill目录，再按本机项目路径配置；不要直接覆盖已有自定义Skill。当前机器仍以原正式安装目录为唯一维护源。

## 历史内容处理

删除失效或重复的规则正文，合并重复经验表；旧提交文件、旧确认范本、原始素材及必要验证记录保留并标明历史用途。不使用批量删除或Git清理去处理被忽略业务目录。

不增加看板、数据库、CI或自动提醒。公开范围与提交核验见[仓库管理说明](仓库管理说明.md)。具体申请结果只在本地档案及台账维护。
