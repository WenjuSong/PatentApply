# 长期问题与解法

来自实际办理反馈，属于项目经验，不是普遍登记规范。具体措辞见模板，授权见项目规则；这里仅保留导致返工的问题及解法。

| 问题 | 固化做法 | 检查依据 |
|---|---|---|
| 每页重复问已知信息，恢复后从头做 | 先信息卡和断点，再当前页面；一次问确实缺失项 | 用户确认来源及当前页面 |
| 新件重写长段落，增加review成本 | 固定背景/工作流/研发/AI分工沿用，只改本件简短事实 | 与确认模板比较差异 |
| “少即是多”被误用为删证据 | 精简图注，完整保留约定的四部分和共用研发九图 | 证据清单及实际页数，总页数不固定 |
| 用生造风格词、叠加动词堆工作量 | 写本人具体行动与画面结果，用确认过的自然表达 | 画面、过程记录与语句主谓 |
| 研发共用却写成单件全部重新完成 | 共用资料与本件记录分开，时间线内部核实 | 实际工具版本/调用与日期 |
| 正式PDF夹带助手备注、重复画面元素 | 审查人员视角，来源/行动/日期一句够用 | 每句是否补充必要事实 |
| 用户只改一句却牵动全文 | 只改指定字段，新版本输出，比较配置差异 | 改动页渲染及原证据hash |
| “创作流程”替换标题触发硬校验 | 平台标题用“创作方法”，正文沿用创作流程 | 当前页面校验，不当全国规定 |
| 低清日期放大仍模糊 | 原页面重截完整帖子，保留原貌 | 落盘截图的账号、作品、日期；年份另有依据 |
| 文件选择失败、中文路径丢字 | 文档化filechooser优先，失败查原因，路径读回 | 实际文件条目与平台查看 |
| 灰色勾选被误判漏项、替换后页数丢失 | 读实际值和动态字段，替换重新核页数 | checked/disabled及PDF实际页数 |
| 平台加水印被误认为本地添加 | 本地hash、渲染与服务器预览分开记录 | 不反复重做已合格本地件 |
| 用户确认后模板仍旧，后续重复犯错 | 更新唯一来源，冻结旧提交件，其他入口只链接 | 匿名模板、本地范本与引用无冲突 |
| 模板通配白名单误纳真实配置 | Git精确列举可公开文件，提交前扫描实际暂存 | 无身份、原件、签名、回执、私密路径 |
| 提交成功误作受理或发证 | 各阶段有对应页面证据才更新 | 回执、查询结果分别记录 |

## 最短复用路线

项目入口与断点 → 本件差异 → 复用文案并确认 → 配置生成与必要渲染 → 上传预览及授权推进 → 本人签字交接 → 最终提交回执 → 个案归档和通用修正。

## 合并维护

稳定边界入AGENTS，步骤入Skill，正文入模板，个案入cases。清理失效说明时直接修改实际生效源，不能用“新规则追加”保留互相矛盾正文。历史记录及提交材料冻结保留，索引标出停用，不删除原素材或业务文件。公开Skill由唯一维护源导出，不手工编辑两份；发布只含明确白名单文件。
